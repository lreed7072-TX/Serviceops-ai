# Plan 01: Bug fixes in qbo-client.ts and qbo-sync.ts

## Objective
Fix three of the four live bugs in the existing QBO client code: sparse update data corruption (FOUND-02), decimal rounding errors (FOUND-03), and missing API version pinning (FOUND-04). The token refresh race condition (FOUND-01) is handled separately in Plan 06 (Wave 2) because it depends on schema fields added by Plan 02. These are all modifications to existing files (`qbo-client.ts` and `qbo-sync.ts`) and must be completed before any new infrastructure is built on top.

## must_haves
- [ ] `updateCustomer()` spreads the full fetched QBO entity before applying ServiceOps changes, preserving all existing QBO fields (phone, address, terms, etc.)
- [ ] All QBO API calls include `?minorversion=75` via the exported `QBO_API_VERSION` constant appended in `qboRequest()`
- [ ] `syncInvoiceToQbo()` line items pass through a `roundQboAmount()` call that rounds Decimal values to 2 decimal places before sending to QBO

<task id="01.02">
<title>Fix sparse update data corruption in updateCustomer()</title>
<action>
In `src/lib/qbo/qbo-client.ts`, replace the `updateCustomer()` function (lines 262-288) with the fetch-merge-POST pattern:

```typescript
export async function updateCustomer(
  connection: QboConnection,
  qboCustomerId: string,
  customerData: {
    displayName: string;
    email?: string | null;
    phone?: string | null;
  }
): Promise<QboCustomer> {
  // 1. Fetch the full existing entity (includes SyncToken and all fields)
  const existing = await getCustomer(connection, qboCustomerId);

  // 2. Merge — spread existing entity, then override only ServiceOps-managed fields
  const merged: Record<string, unknown> = {
    ...(existing as Record<string, unknown>), // Preserve all QBO fields
    DisplayName: customerData.displayName,
  };

  // Only override email/phone if explicitly provided
  if (customerData.email !== undefined) {
    merged.PrimaryEmailAddr = customerData.email
      ? { Address: customerData.email }
      : undefined;
  }
  if (customerData.phone !== undefined) {
    merged.PrimaryPhone = customerData.phone
      ? { FreeFormNumber: customerData.phone }
      : undefined;
  }

  // 3. POST the complete merged payload
  const result = (await qboRequest(connection, "POST", "customer", merged)) as {
    Customer: QboCustomer;
  };
  return result.Customer;
}
```

Key differences from the old code:
- Spreads `...existing` so all QBO fields (BillAddr, ShipAddr, Notes, PaymentMethodRef, SalesTermRef, etc.) are preserved
- SyncToken is automatically included via the spread (no longer manually extracted)
- Only overrides fields that ServiceOps explicitly manages
- Uses `!== undefined` checks so passing `null` explicitly clears a field, but omitting it preserves the existing value
</action>

Verify: The old pattern of `const qboCustomer = { Id: qboCustomerId, SyncToken: ... }` is completely gone.
Verify: The function still calls `getCustomer()` first (which was already there).
</verify>
</task>

<action>

1. First, add the `roundQboAmount` helper at the top of the file. Add this import and function after the existing imports (after line 8):

```typescript
/**
 * Round a Decimal/number to 2 decimal places for QBO API compatibility.
 * QBO validates amounts to 2 decimal places; IEEE 754 floating point
 * can produce artifacts like 123.45000000000000284217... from Prisma Decimal.
 */
function roundQboAmount(value: { toFixed(digits: number): string } | number | string): number {
  if (typeof value === "object" && value !== null && "toFixed" in value) {
    return Number(value.toFixed(2));
  }
  return Number(Number(value).toFixed(2));
}
```

Note: This is a local helper in qbo-sync.ts for the immediate fix. The canonical exported version will live in `qbo-mapper.ts` (Plan 04, FOUND-08). Once qbo-mapper.ts exists, this local copy can be replaced with an import in a future cleanup pass.

