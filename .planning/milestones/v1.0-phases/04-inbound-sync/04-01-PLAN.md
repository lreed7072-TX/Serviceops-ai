# Plan 04-01: QboInvoice Type Fix + Inbound Sync Functions

## Goal

Add the missing `status` field to the `QboInvoice` type for void detection, then implement the four new sync functions that handle inbound entity processing from QBO: invoice CDC change detection (void, full payment, partial payment), outbound void when ServiceOps cancels an invoice, and inbound customer sync with conflict resolution.

## must_haves

- `QboInvoice` type includes `status?: string` field for void detection
- `processInboundCustomer()` creates or updates a ServiceOps customer from QBO CDC data using `fromQboCustomer()` mapper with field-ownership split (QBO wins billing fields, ServiceOps wins operational fields)
- `processCdcCustomerPull()` fetches QBO customer by ID then delegates to `processInboundCustomer()`
- `processCdcInvoiceChange()` detects voided invoices (`status === "Voided"` -> mark CANCELED), full payments (`Balance === 0` -> mark PAID), and partial payments (log only)
- `processVoidInvoiceInQbo()` fetches fresh SyncToken then calls `voidInvoice()`, with guard against already-voided invoices
- All functions log actions to `QboSyncLog` with descriptive metadata
- All functions use the established `getActiveConnection()` pattern
- No-op guard: CDC invoice processing skips if ServiceOps invoice is already in the correct state

<task id="04-01-02">
<title>Implement processInboundCustomer sync function</title>
<description>
Add `processInboundCustomer()` to `src/lib/qbo/qbo-sync.ts`. This function handles SYNC-02 customer inbound sync with conflict resolution.

Import `fromQboCustomer` from `./qbo-mapper` and `QboCustomer` from `./qbo-types`.

Function signature:
```typescript
export async function processInboundCustomer(
  orgId: string,
  qboCustomer: QboCustomer,
  connectionId: string
): Promise<{ success: boolean; action: "created" | "updated" | "skipped"; error?: string }>
```

Lookup flow:
1. Find ServiceOps customer by `qboCustomerId` match: `prisma.customer.findFirst({ where: { qboCustomerId: qboCustomer.Id, orgId } })`
2. If not found, fallback to email match: `prisma.customer.findFirst({ where: { primaryEmail: qboCustomer.PrimaryEmailAddr?.Address, orgId } })` (only if email exists)
3. Extract QBO-wins fields via `fromQboCustomer(qboCustomer)` — returns name, primaryEmail, primaryPhone, billingStreet1/City/State/PostalCode

If found (update path):
- `prisma.customer.update({ where: { id }, data: { ...fields, qboCustomerId: qboCustomer.Id } })`
- Log to QboSyncLog with `action: "pull"`, `metadata: { source: "qbo_cdc", fieldsUpdated: Object.keys(fields) }`
- Return `{ success: true, action: "updated" }`

If not found (create path):
- `prisma.customer.create({ data: { orgId, qboCustomerId: qboCustomer.Id, ...fields } })`
- Note: `createdByUserId` is nullable on Customer model — omit it for CDC-created records
- Log to QboSyncLog with `metadata: { source: "qbo_cdc", action: "created_inbound" }`
- Return `{ success: true, action: "created" }`

Important: Do NOT propagate `Active: false` from QBO to ServiceOps `status` field. ServiceOps wins on status. If QBO `Active === false`, log it in QboSyncLog metadata as `{ qboActive: false }` but do not change ServiceOps status.

Wrap in try/catch, log failures to QboSyncLog, return `{ success: false, action: "skipped", error }`.
</description>

<task id="04-01-03">
<title>Implement processCdcCustomerPull wrapper function</title>
<description>
Add `processCdcCustomerPull()` to `src/lib/qbo/qbo-sync.ts`. This is a thin wrapper that the cron flush dispatcher calls — it fetches the QBO customer by ID, then delegates to `processInboundCustomer()`.

Import `getCustomer` from `./qbo-client` (already imported).

```typescript
export async function processCdcCustomerPull(
  orgId: string,
  qboCustomerId: string,
  realmId: string
): Promise<{ success: boolean; error?: string }> {
  const connection = await prisma.qboConnection.findFirst({
    where: { orgId, realmId, isActive: true },
  });
  if (!connection) return { success: false, error: `No active QBO connection for realm ${realmId}` };

  try {
    const qboCustomer = await getCustomer(connection, qboCustomerId);
    const result = await processInboundCustomer(orgId, qboCustomer, connection.id);
    return { success: result.success, error: result.error };
  } catch (err) {
    const errorMessage = err instanceof Error ? err.message : "Unknown error";
    await prisma.qboSyncLog.create({
      data: {
        orgId, connectionId: connection.id, entityType: "customer",
        entityId: orgId, qboEntityId: qboCustomerId, action: "pull",
        status: "failed", errorMessage,
      },
    });
    return { success: false, error: errorMessage };
  }
}
```

Note: uses `prisma.qboConnection.findFirst` with `realmId` (same pattern as `processPaymentJob`).

<task id="04-01-04">
<title>Implement processCdcInvoiceChange sync function</title>
<description>
Add `processCdcInvoiceChange()` to `src/lib/qbo/qbo-sync.ts`. This handles PAY-02 inbound: detects void, partial payment balance changes, and full payments delivered via CDC.

```typescript
export async function processCdcInvoiceChange(
  orgId: string,
  qboInvoiceId: string,
  realmId: string
): Promise<{ success: boolean; error?: string }>
```

Flow:
1. Get connection: `prisma.qboConnection.findFirst({ where: { orgId, realmId, isActive: true } })`
2. Fetch QBO invoice: `getInvoice(connection, qboInvoiceId)` — this returns the full entity including `status` and `Balance`
3. Find ServiceOps invoice: `prisma.invoice.findFirst({ where: { orgId, qboInvoiceId } })`
4. If no matching ServiceOps invoice, log and return success (QBO invoice not tracked in ServiceOps)

Detection logic (in order):
- **Void detection:** If `qboInvoice.status === "Voided"`:
  - If ServiceOps invoice is already `CANCELED`, skip (no-op)
  - Otherwise: `prisma.invoice.update({ where: { id }, data: { status: "CANCELED" } })`
  - Log to QboSyncLog: `action: "pull"`, `metadata: { source: "qbo_cdc", voided: true }`
  - Return success

- **Full payment (not voided):** If `qboInvoice.Balance === 0`:
  - If ServiceOps invoice is already `PAID`, skip (no-op)
  - Otherwise: `prisma.invoice.update({ where: { id }, data: { status: "PAID", paidAt: new Date() } })`
  - Log: `metadata: { source: "qbo_cdc", fullyPaid: true, balance: 0 }`
  - Return success

- **Partial payment:** If `qboInvoice.Balance > 0` and `qboInvoice.Balance < qboInvoice.TotalAmt`:
  - Do NOT change invoice status
  - Log: `metadata: { source: "qbo_cdc", remainingBalance: qboInvoice.Balance, note: "Partial payment" }`
  - Return success

- **No change:** If none of the above, return success (self-originated CDC entity)

Important: Use `InvoiceStatus` enum value `"CANCELED"` (single L, matches Prisma enum). The enum import `import { InvoiceStatus } from "@prisma/client"` is not currently in qbo-sync.ts — do NOT add an unnecessary import; just use the string literal `"CANCELED"` and `"PAID"` which match the enum values.

Wrap in try/catch, log failures.
</description>

<task id="04-01-05">
<title>Implement processVoidInvoiceInQbo outbound function</title>
<description>
Add `processVoidInvoiceInQbo()` to `src/lib/qbo/qbo-sync.ts`. This handles PAY-02 outbound: when a ServiceOps invoice is CANCELED, void the corresponding QBO invoice.

Import `voidInvoice` from `./qbo-client` (add to existing import statement).

```typescript
export async function processVoidInvoiceInQbo(
  orgId: string,
  invoiceId: string
): Promise<{ success: boolean; error?: string }>
```

Flow:
1. Get active connection: `getActiveConnection(orgId)`
2. Find ServiceOps invoice: `prisma.invoice.findFirst({ where: { id: invoiceId, orgId } })`
3. Guard: if no `qboInvoiceId`, return `{ success: false, error: "Invoice not synced to QBO" }`
4. Fetch current QBO invoice to get fresh SyncToken: `getInvoice(connection, invoice.qboInvoiceId)`
5. **Guard against already voided:** If `qboInvoice.status === "Voided"`, log success and return without calling void API (prevents Risk 7 from research)
6. Call `voidInvoice(connection, invoice.qboInvoiceId, qboInvoice.SyncToken)`
7. Log success to QboSyncLog: `action: "void"`, `status: "success"`

The SyncToken is fetched fresh because ServiceOps does not store it. The existing retry infrastructure in qbo-queue handles stale SyncToken errors (Risk 5).

Wrap in try/catch, log failures.
</description>
