<title>Add Send via QBO button to invoice detail page</title>
<file>src/app/(app)/invoices/[id]/page.tsx</file>
<action>modify</action>
<description>
1. Add `qboInvoiceId: string | null` to the Invoice type definition at the top of the file (add after the `paidAt` field).

2. Add state for the QBO send action:
   ```typescript
   const [sendingQbo, setSendingQbo] = useState(false);
   ```

3. Add the handler function:
   ```typescript
   const sendViaQbo = async () => {
     if (!invoiceId || !invoice?.qboInvoiceId) return;
     setSendingQbo(true);
     try {
       const res = await apiFetch("/api/integrations/qbo/send-invoice-email", {
         method: "POST",
         headers: { "Content-Type": "application/json" },
         body: JSON.stringify({ invoiceId }),
       });
       if (!res.ok) {
         const data = await res.json();
         throw new Error(data.error || "Failed to send via QBO");
       }
       const data = await res.json();
       toast.success(data.data.message);
     } catch (e: any) {
       toast.error(e?.message ?? "Failed to send invoice via QBO");
     } finally {
       setSendingQbo(false);
     }
   };
   ```

4. Add the button in the Actions card, after the "Email to Customer" button (around line 287):
   ```tsx
   {invoice.qboInvoiceId && (
     <button
       onClick={sendViaQbo}
       disabled={sendingQbo}
       className="btn btn-primary"
       style={{ fontSize: 14, padding: "8px 16px" }}
     >
       {sendingQbo ? "Sending..." : "Send via QBO"}
     </button>
   )}
   ```

   Use `btn-primary` (orange accent) to distinguish from the outline buttons. This button only renders when the invoice has been synced to QBO.

5. Also include the API response in the invoice fetch — make sure the GET endpoint for invoices returns `qboInvoiceId`. The existing API likely already returns it since it returns the full invoice record.
</description>
<verify>
The button appears only when `invoice.qboInvoiceId` is truthy. Clicking calls the send-invoice-email endpoint. Toast shows success/error.
</verify>
</task>

<title>Create QBO health dashboard page</title>
<file>src/app/(app)/settings/integrations/qbo-health/page.tsx</file>
<action>create</action>
<description>
Create the health dashboard page at `/settings/integrations/qbo-health`. This is a client component that fetches from the 3 health API endpoints.

Structure:
1. **Breadcrumbs**: Settings > Integrations > QBO Health
2. **Connection Status Card**: Company name, realm ID, connected date, token expiry countdown (days remaining), last sync time. Green/red status indicator.
3. **Queue Status Bar**: Stat cards showing Pending, Processing, Failed, Completed counts from queueStats.
4. **Sync Overview Section**: Grid of cards, one per entity type (Customer, Invoice, Item, Estimate, Payment). Each card shows:
   - Entity type name with icon
   - Last sync time (relative, e.g., "2 hours ago")
   - Success/Failed counts
   - Manual Sync button (calls POST /api/integrations/qbo/sync-trigger with the entity type)
5. **Error Log Section**: Table showing failed sync logs, filterable by entity type. Columns: Time, Entity Type, Error Message, Resolution Hint, Actions (Re-trigger button). Pagination via Load More. Re-trigger button calls POST /api/integrations/qbo/sync-trigger with the specific entity.
6. **Dead Letter Section**: If deadLetterCount > 0, show a warning card with the count and a link to view details.

State management:
- `health` state from GET /api/integrations/qbo/health
- `logs` state from GET /api/integrations/qbo/sync-logs?status=failed
- `syncing` record tracking which entity types are currently syncing
- `triggerSync(entityType)` function that calls POST /api/integrations/qbo/sync-trigger

Follow existing page patterns:
- Use `apiFetch` for API calls
- Use `useToast()` for feedback
- Use `LoadingSpinner` for loading states
- Orange accent for action buttons
- Import Lucide icons: `RefreshCw`, `CheckCircle`, `XCircle`, `AlertTriangle`, `Clock`, `Users`, `FileText`, `Package`, `Receipt`, `Calculator`

Import the CSS file: `import "./qbo-health.css"`
</description>
<verify>
File exists at the correct Next.js route path. Page fetches health and sync-logs data. Manual sync buttons call the sync-trigger endpoint. Error log displays resolution hints.
</verify>
</task>
