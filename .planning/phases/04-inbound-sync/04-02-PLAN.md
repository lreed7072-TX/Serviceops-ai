# Plan 04-02: CDC Cron Route + Flush Dispatcher Extension

## Goal

Build the CDC polling engine that runs every 4 hours, polling QBO's Change Data Capture endpoint for Customer and Invoice changes across all connected orgs, enqueuing discovered changes to the sync job queue. Extend the existing qbo-flush cron dispatcher to handle the three new inbound job types (`invoice:pull`, `customer:pull`, `invoice:void`). Register the new CDC cron in `vercel.json`.

## must_haves

- CDC cron route at `/api/cron/qbo-cdc` secured by `CRON_SECRET`
- Polls QBO CDC for `Customer,Invoice` entities per org using `cdcRequest()`
- Creates or updates `QboCdcCursor` per org with upsert on `orgId`
- First-run default: `lastPollAt = now - 4 hours` (avoids large historical backlog)
- On success: advances `lastPollAt` to `now`, sets `lastPollStatus = "success"`
- On failure: does NOT advance `lastPollAt`, sets `lastPollStatus = "failed"` with error message
- Multi-org isolation: one org's failure does not block other orgs
- Enqueues `customer:pull` and `invoice:pull` jobs with `qboEntityId` and `qboRealmId` for dedup
- Flush dispatcher handles `invoice:pull` -> `processCdcInvoiceChange()`
- Flush dispatcher handles `customer:pull` -> `processCdcCustomerPull()`
- Flush dispatcher handles `invoice:void` -> `processVoidInvoiceInQbo()`
- `vercel.json` includes `qbo-cdc` cron at `0 */4 * * *`
- Returns stats: `{ orgsPolled, customersQueued, invoicesQueued, errors }`

```typescript
import { NextRequest, NextResponse } from "next/server";
import { prisma } from "@/lib/prisma";
import { cdcRequest } from "@/lib/qbo/qbo-client";
import { enqueue } from "@/lib/qbo/qbo-queue";
import type { QboCdcResponse } from "@/lib/qbo/qbo-types";
import type { QboConnection } from "@prisma/client";
```

**GET handler:**
1. Verify `authorization` header matches `Bearer ${process.env.CRON_SECRET}`. Return 401 if not.
2. Initialize stats object: `{ orgsPolled: 0, customersQueued: 0, invoicesQueued: 0, errors: 0 }`
3. Fetch all active connections: `prisma.qboConnection.findMany({ where: { isActive: true } })`
4. For each connection, call `pollOrgCdc(connection, stats)` inside a try/catch. On catch: `stats.errors++`, update cursor with failure status.
5. After loop: `stats.orgsPolled = connections.length`
6. Return `{ data: stats }`

**pollOrgCdc(connection, stats) helper function:**
1. Get or create cursor:
   ```typescript
   let cursor = await prisma.qboCdcCursor.findUnique({ where: { orgId: connection.orgId } });
   const now = new Date();
   if (!cursor) {
     // First run: look back one poll interval (4 hours)
     const fourHoursAgo = new Date(now.getTime() - 4 * 60 * 60 * 1000);
     cursor = await prisma.qboCdcCursor.create({
       data: {
         orgId: connection.orgId,
         connectionId: connection.id,
         lastPollAt: fourHoursAgo,
         lastPollStatus: "success",
         entityTypes: "Customer,Invoice",
       },
     });
   }
   ```

2. Call CDC: `const cdcResponse = await cdcRequest(connection, ["Customer", "Invoice"], cursor.lastPollAt)`

3. Parse entities using `parseCdcEntities()` helper (see next task item inline):
   ```typescript
   const customers = parseCdcEntities(cdcResponse, "Customer");
   const invoices = parseCdcEntities(cdcResponse, "Invoice");
   ```

4. Enqueue customer jobs (dedup check first):
   ```typescript
   for (const cust of customers) {
     const qboId = (cust as { Id: string }).Id;
     // Dedup: skip if pending/claimed job exists for this qboEntityId
     const existing = await prisma.qboSyncJob.findFirst({
       where: { qboEntityId: qboId, entityType: "customer", status: { in: ["pending", "claimed"] } },
       select: { id: true },
     });
     if (existing) continue;

     const job = await enqueue(connection.orgId, connection.id, "customer", connection.orgId, "pull", 5,
       { qboEntityId: qboId, realmId: connection.realmId });
     await prisma.qboSyncJob.update({ where: { id: job.id }, data: { qboEntityId: qboId, qboRealmId: connection.realmId } });
     stats.customersQueued++;
   }
   ```

5. Enqueue invoice jobs (same dedup pattern):
   ```typescript
   for (const inv of invoices) {
     const qboId = (inv as { Id: string }).Id;
     const existing = await prisma.qboSyncJob.findFirst({
       where: { qboEntityId: qboId, entityType: "invoice", status: { in: ["pending", "claimed"] } },
       select: { id: true },
     });
     if (existing) continue;

     const job = await enqueue(connection.orgId, connection.id, "invoice", connection.orgId, "pull", 5,
       { qboEntityId: qboId, realmId: connection.realmId });
     await prisma.qboSyncJob.update({ where: { id: job.id }, data: { qboEntityId: qboId, qboRealmId: connection.realmId } });
     stats.invoicesQueued++;
   }
   ```

6. Update cursor on success:
   ```typescript
   await prisma.qboCdcCursor.update({
     where: { orgId: connection.orgId },
     data: { lastPollAt: now, lastPollStatus: "success", lastPollError: null },
   });
   ```

7. Log a warning if entity count equals CDC max (1000) — signals possible truncation:
   ```typescript
   if (customers.length >= 1000 || invoices.length >= 1000) {
     console.warn(`CDC truncation warning for org ${connection.orgId}: customers=${customers.length}, invoices=${invoices.length}`);
   }
   ```

**parseCdcEntities helper (inline in the same file):**
```typescript
function parseCdcEntities(cdcResponse: QboCdcResponse, entityName: string): unknown[] {
  const result: unknown[] = [];
  for (const cdcItem of cdcResponse.CDCResponse) {
    for (const qr of cdcItem.QueryResponse) {
      const entities = (qr as Record<string, unknown>)[entityName];
      if (Array.isArray(entities)) {
        result.push(...entities);
      }
    }
  }
  return result;
}
```

**Failure handling in the outer loop (when pollOrgCdc throws):**
```typescript
await prisma.qboCdcCursor.upsert({
  where: { orgId: connection.orgId },
  create: {
    orgId: connection.orgId, connectionId: connection.id,
    lastPollAt: new Date(Date.now() - 4 * 60 * 60 * 1000),
    lastPollStatus: "failed", lastPollError: errorMessage,
    entityTypes: "Customer,Invoice",
  },
  update: {
    lastPollStatus: "failed", lastPollError: errorMessage,
    // lastPollAt NOT updated — retry from same window on next run
  },
});
```

<title>Add inbound job handlers to qbo-flush dispatcher</title>
<description>
Modify `src/app/api/cron/qbo-flush/route.ts` to handle three new job types in the `dispatchJob` switch.

1. Add imports for the new sync functions:
   ```typescript
   import {
     syncCustomerToQbo,
     syncInvoiceToQbo,
     syncMaterialToQbo,
     syncLaborRateToQbo,
     syncQuoteToQbo,
     processPaymentJob,
     processCdcInvoiceChange,
     processCdcCustomerPull,
     processVoidInvoiceInQbo,
   } from "@/lib/qbo/qbo-sync";
   ```

2. Add these three cases BEFORE the `default` case in the switch:

   ```typescript
   case "invoice:pull": {
     const qboInvoiceId = (payload.qboEntityId as string) || job.qboEntityId;
     const realmId = (payload.realmId as string) || job.qboRealmId;
     if (!qboInvoiceId || !realmId) {
       throw new Error("invoice:pull missing qboEntityId or realmId");
     }
     const invPullResult = await processCdcInvoiceChange(job.orgId, qboInvoiceId, realmId);
     if (!invPullResult.success) throw new Error(invPullResult.error || "Invoice CDC processing failed");
     break;
   }

   case "customer:pull": {
     const qboCustomerId = (payload.qboEntityId as string) || job.qboEntityId;
     const realmId = (payload.realmId as string) || job.qboRealmId;
     if (!qboCustomerId || !realmId) {
       throw new Error("customer:pull missing qboEntityId or realmId");
     }
     const custPullResult = await processCdcCustomerPull(job.orgId, qboCustomerId, realmId);
     if (!custPullResult.success) throw new Error(custPullResult.error || "Customer inbound sync failed");
     break;
   }

   case "invoice:void": {
     const voidResult = await processVoidInvoiceInQbo(job.orgId, job.entityId);
     if (!voidResult.success) throw new Error(voidResult.error || "Invoice void failed");
     break;
   }
   ```

Pattern notes:
- `invoice:pull` and `customer:pull` extract `qboEntityId` from payload (set by webhook/CDC) or from the job's `qboEntityId` field
- `invoice:void` uses `job.entityId` which is the ServiceOps invoice ID (set by the void trigger in PLAN-03)
- Variable names use unique prefixes (`invPullResult`, `custPullResult`, `voidResult`) to avoid shadowing
