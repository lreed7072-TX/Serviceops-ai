# Plan 04-03: Invoice Cancellation Void Trigger

## Goal

Wire the outbound void trigger into the invoice PATCH endpoint. When a ServiceOps invoice status transitions to `CANCELED` and the invoice has a `qboInvoiceId`, enqueue an `invoice:void` job to the sync queue. This completes the outbound direction of PAY-02 (ServiceOps cancellation -> QBO void).

## must_haves

- When invoice status changes to `CANCELED` in the PATCH route: enqueue `invoice:void` job if `qboInvoiceId` exists
- Job uses priority 1 (user-triggered, near-real-time processing)
- Enqueue is fire-and-forget (does not block the HTTP response)
- Does not enqueue if invoice has no `qboInvoiceId` (not synced to QBO)
- Does not break existing SENT -> QBO sync trigger logic
- Uses the established `enqueue()` function from `qbo-queue`

2. After the existing SENT trigger block (lines ~117-125), add the CANCELED trigger. Place it AFTER the `prisma.invoice.update()` call (line ~114) and after the existing SENT block:

   ```typescript
   // When status changes to CANCELED, trigger QBO void if synced
   if (body?.status === "CANCELED" && existing.status !== "CANCELED") {
     if (existing.qboInvoiceId) {
       getActiveConnection(orgId).then((conn) => {
         if (conn) {
           enqueue(orgId, conn.id, "invoice", id, "void", 1).catch((err) => {
             console.error("Failed to enqueue QBO void job:", err);
           });
         }
       });
     }
   }
   ```

Pattern notes:
- Uses `body?.status === "CANCELED"` (string literal matching the InvoiceStatus enum value with single L)
- Uses `existing.status !== "CANCELED"` to prevent re-enqueuing if already canceled
- Checks `existing.qboInvoiceId` (the pre-update value — which is correct since qboInvoiceId doesn't change during a status update)
- Fire-and-forget with `.then()` + `.catch()` — same pattern as the existing SENT trigger
- Priority 1 = user-triggered (same convention as manual sync triggers)
- `id` is the invoice ID (from URL params), used as `entityId` in the job — this is what `processVoidInvoiceInQbo` expects
