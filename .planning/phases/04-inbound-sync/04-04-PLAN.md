# Plan 04-04: Unit Tests for Inbound Sync, CDC, and Void

## Goal

Write comprehensive unit tests for all Phase 4 functionality: the four new sync functions, the CDC cron route, and the flush dispatcher's new inbound job handlers. Tests follow the established vitest patterns from Phase 3 (mock prisma, mock qbo-client, shared fixtures).

## must_haves

- Tests for `processInboundCustomer`: update by QBO ID, update by email fallback, create new, inactive customer guard, conflict logging
- Tests for `processCdcInvoiceChange`: void detection, full payment, partial payment (log only), no-op when already in correct state
- Tests for `processVoidInvoiceInQbo`: successful void, already-voided guard, no QBO connection guard
- Tests for CDC cron: cursor creation (first run), cursor advance on success, cursor NOT advanced on failure, multi-org isolation
- Tests for flush dispatcher: `invoice:pull`, `customer:pull`, `invoice:void` routing
- All tests pass: `npx vitest run src/__tests__/lib/qbo/`
