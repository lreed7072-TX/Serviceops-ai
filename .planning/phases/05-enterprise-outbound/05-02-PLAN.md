# Plan 05-02: Sync Functions + Flush Dispatcher Extension

## Objective
Implement the 5 new sync functions (vendor, employee, time entry, expense/bill, credit memo) in qbo-sync.ts, plus the resolveOrCreateQboClass and fetchAndCachePreferences helpers. Extend the flush dispatcher with 5 new cases to route queued jobs to these sync functions.

## must_haves
- syncVendorToQbo() uses resolveOrCreateQboEntity for DisplayName collision handling
- syncEmployeeToQbo() enforces TECH role guard before syncing to QBO
- syncTimeEntryToQbo() cascades employee + customer sync before creating TimeActivity
- syncTimeEntryToQbo() guards on status === STOPPED before syncing
- syncTimeEntryToQbo() computes hours/minutes from accumulatedSeconds
- syncExpenseToQbo() branches Bill vs Purchase based on material.vendorId presence
- syncExpenseToQbo() cascades vendor sync when Bill path and vendor lacks qboVendorId
- syncExpenseToQbo() uses account mapping gate (requireAccountMapping)
- syncCreditMemoToQbo() creates LinkedTxn referencing the original QBO invoice
- resolveOrCreateQboClass() returns null when classTrackingEnabled is false (silently skips)
- fetchAndCachePreferences() updates QboConnection with classTrackingEnabled and locationTrackingEnabled
- Flush dispatcher handles vendor:push, employee:push, timeActivity:push, expense:push, creditMemo:push
- All sync functions follow established pattern: getActiveConnection guard, try/catch, QboSyncLog on success/failure
- Build passes with zero TypeScript errors

<title>Sync functions: syncVendorToQbo and syncEmployeeToQbo</title>
<details>
Add to `src/lib/qbo/qbo-sync.ts`:

**Import additions at top of file:**
- From qbo-client: `createEmployee, getEmployee, updateEmployee, createVendor, getVendor, updateVendor, createClass, queryClasses, getPreferences, createTimeActivity, createBill, createPurchase, createCreditMemo`
- From qbo-mapper: `toQboEmployee, toQboVendor, toQboTimeActivity, toQboBill, toQboPurchase, toQboCreditMemo`
- From qbo-types: `QboEmployee, QboVendor, QboRef, QboClass`

**syncVendorToQbo(orgId: string, vendorId: string): Promise<{success: boolean; qboVendorId?: string; error?: string}>**

Flow:
1. `getActiveConnection(orgId)` guard
2. Fetch Vendor from DB: `prisma.vendor.findFirst({ where: { id: vendorId, orgId } })`
3. If `vendor.qboVendorId` exists → fetch existing via `getVendor()`, merge via `toQboVendor(vendor, existing)`, call `updateVendor()`
4. If no qboVendorId → use `resolveOrCreateQboEntity<QboVendor>()`:
   - entityType: `"Vendor"` (QBO IQL entity name for query)
   - displayName: `vendor.name`
   - matchFn: `(existing) => !!vendor.email && existing.PrimaryEmailAddr?.Address?.toLowerCase() === vendor.email.toLowerCase()`
   - createFn: `() => createVendor(connection, toQboVendor(vendor))`
5. Update vendor record: `prisma.vendor.update({ where: { id: vendorId }, data: { qboVendorId: result.Id, qboSyncedAt: new Date() } })`
6. Log success to QboSyncLog
7. Return `{ success: true, qboVendorId: result.Id }`

**syncEmployeeToQbo(orgId: string, userId: string): Promise<{success: boolean; qboEmployeeId?: string; error?: string}>**

Flow:
1. `getActiveConnection(orgId)` guard
2. Fetch User: `prisma.user.findFirst({ where: { id: userId, orgId, role: "TECH" } })`
3. Guard: if no user found, return error "User not found or not a TECH role"
4. If `user.qboEmployeeId` exists → fetch existing via `getEmployee()`, merge, `updateEmployee()`
5. If no qboEmployeeId → use `resolveOrCreateQboEntity<QboEmployee>()`:
   - entityType: `"Employee"`
   - displayName: `user.name ?? user.email.split("@")[0]`
   - matchFn: `(existing) => existing.PrimaryEmailAddr?.Address?.toLowerCase() === user.email.toLowerCase()`
   - createFn: `() => createEmployee(connection, toQboEmployee(user))`
6. Update user record: `prisma.user.update({ where: { id: userId }, data: { qboEmployeeId: result.Id } })`
7. Log success, return `{ success: true, qboEmployeeId: result.Id }`

Both functions: wrap in try/catch, log errors to QboSyncLog with `action: "vendor:push"` / `"employee:push"`, return `{ success: false, error: message }`.

<title>Sync functions: syncTimeEntryToQbo and syncExpenseToQbo</title>
<details>
Add to `src/lib/qbo/qbo-sync.ts`:

**syncTimeEntryToQbo(orgId: string, timeEntryId: string): Promise<{success: boolean; qboTimeActivityId?: string; error?: string}>**

Flow:
1. `getActiveConnection(orgId)` guard
2. Fetch TimeEntry with includes: `{ user: true, task: { include: { workOrder: { include: { customer: true } } } } }`
   - Note: TimeEntry connects to WorkOrder through Task/TaskInstance. Verify the actual relation path in the schema and adjust the include accordingly.
3. Guard: `timeEntry.status !== "STOPPED"` → return error "TimeEntry must be STOPPED to sync"
4. Guard: `timeEntry.user.role !== "TECH"` → return error "Only TECH users sync as QBO employees"
5. Already synced guard: if `qboTimeActivityId` exists → return `{ success: true, qboTimeActivityId }`
6. **Cascade employee:** if `timeEntry.user.qboEmployeeId` is null → call `syncEmployeeToQbo(orgId, timeEntry.userId)`. Re-fetch user for fresh qboEmployeeId.
7. **Cascade customer:** Get customer from workOrder chain. If `customer.qboCustomerId` is null → call `syncCustomerToQbo(orgId, customer.id)`. Re-fetch for qboCustomerId.
8. **Optional ItemRef:** Check if task has a linked labor rate with qboItemId. If so, use it. Otherwise skip.
9. **Billable classification:** `billable = workOrder.sourceWorkflowId ? false : true` (PM-generated WOs are non-billable)
10. **Class tracking:** `const classRef = await resolveOrCreateQboClass(connection, orgId, workOrder.orderType)`
11. **Compute time:** `const totalSeconds = timeEntry.accumulatedSeconds`; derive hours/minutes
12. Build payload via `toQboTimeActivity(timeEntry, qboEmployeeId, qboCustomerId, { qboItemId, classRef, billable })`
13. `createTimeActivity(connection, payload)` → store qboTimeActivityId on TimeEntry
14. Log success

**syncExpenseToQbo(orgId: string, stockMovementId: string): Promise<{success: boolean; qboExpenseId?: string; error?: string}>**

Flow:
1. `getActiveConnection(orgId)` guard
2. `requireAccountMapping(orgId)` — account mapping gate
3. Fetch StockMovement with includes: `{ material: { include: { vendor: true } } }`
4. Guard: `movementType !== "PURCHASE"` → return error
5. Guard: totalCost is null/zero → skip
6. Already synced guard: if `qboBillId` or `qboPurchaseId` exists → return success
7. **Expense account category:** if `material.vendor?.vendorType === "SUBCONTRACTOR"` → use `getAccountMapping(orgId, "subcontractor_expense")`; else use `getAccountMapping(orgId, "job_cost_expense")`
8. **Class tracking:** Attempt to find linked workOrder through material usage. If found, resolve class. If not, classRef = undefined.
9. **Bill path (vendor linked):**
   - If `material.vendorId` non-null:
     - Cascade vendor: if `material.vendor.qboVendorId` is null → `syncVendorToQbo(orgId, material.vendorId)`, re-fetch
     - `toQboBill(stockMovement, material, qboVendorId, expenseAccountRef, { classRef })`
     - `createBill(connection, payload)` → store `qboBillId` on StockMovement
10. **Purchase path (no vendor):**
    - `toQboPurchase(stockMovement, material, expenseAccountRef, { classRef })`
    - `createPurchase(connection, payload)` → store `qboPurchaseId` on StockMovement
11. Log success

<title>Sync function: syncCreditMemoToQbo + resolveOrCreateQboClass + fetchAndCachePreferences helpers</title>
<details>
Add to `src/lib/qbo/qbo-sync.ts`:

**syncCreditMemoToQbo(orgId: string, invoiceId: string): Promise<{success: boolean; qboCreditMemoId?: string; error?: string}>**

Flow:
1. `getActiveConnection(orgId)` guard
2. Fetch Invoice with includes: `{ customer: true, lineItems: true, workOrder: true }`
3. Guard: must have `qboInvoiceId` — return error "Invoice must be synced to QBO before issuing credit memo"
4. Guard: must have `customer.qboCustomerId` — if null, cascade `syncCustomerToQbo(orgId, invoice.customerId)`, re-fetch
5. Already synced guard: if `qboCreditMemoId` exists → return success
6. **Class tracking:** if invoice.workOrderId → resolve class from workOrder.orderType
7. Build payload: `toQboCreditMemo(invoice, invoice.lineItems, customer.qboCustomerId, invoice.qboInvoiceId, { classRef })`
8. `createCreditMemo(connection, payload)` → store `qboCreditMemoId` on Invoice
9. Log success

**resolveOrCreateQboClass(connection: QboConnection, orgId: string, orderType: string): Promise<QboRef | null>**

This is an internal helper (export it for testing), NOT a top-level sync function.

Flow:
1. Check `connection.classTrackingEnabled` — if false or null → return `null`
2. Query DB: `prisma.qboClassMap.findUnique({ where: { orgId_orderType: { orgId, orderType } } })`
3. If found → return `{ value: map.qboClassId, name: map.qboClassName }`
4. If not found → auto-create:
   - Map orderType to human-readable name: WORK_ORDER→"Work Order", SALES_ORDER→"Sales Order", PROJECT→"Project"
   - `const qboClass = await createClass(connection, { Name: className })`
   - Upsert: `prisma.qboClassMap.upsert({ where: { orgId_orderType: { orgId, orderType } }, create: { orgId, orderType, qboClassId: qboClass.Id, qboClassName: className }, update: { qboClassId: qboClass.Id, qboClassName: className } })`
   - Return `{ value: qboClass.Id, name: className }`
5. Wrap in try/catch — on error, log warning and return `null` (class tracking failure must NEVER block a sync)

**fetchAndCachePreferences(connection: QboConnection): Promise<{classTrackingEnabled: boolean; locationTrackingEnabled: boolean}>**

Flow:
1. `getPreferences(connection)` — fetch from QBO API
2. Extract: `classTrackingEnabled = prefs.AccountingInfoPrefs?.ClassTrackingPerTxn === true || prefs.AccountingInfoPrefs?.ClassTrackingPerTxnLine === true`
3. Extract: `locationTrackingEnabled = prefs.AccountingInfoPrefs?.TrackDepartments === true`
4. Update: `prisma.qboConnection.update({ where: { id: connection.id }, data: { classTrackingEnabled, locationTrackingEnabled, preferencesLastCheckedAt: new Date() } })`
5. Return `{ classTrackingEnabled, locationTrackingEnabled }`
