# Plan 05-03: Class Tracking Retrofit + Preferences Check + API Routes + UI

## Objective
Retrofit existing sync functions (syncInvoiceToQbo, syncQuoteToQbo) with ClassRef support, wire preferences fetching into the CDC cron, build Vendor CRUD API routes, the credit memo trigger endpoint, extend sync-trigger for new entity types, and add the class tracking warning banner and Issue Credit button to the UI.

## must_haves
- syncInvoiceToQbo includes ClassRef from workOrder.orderType when class tracking is enabled
- syncQuoteToQbo includes ClassRef from workOrder.orderType when class tracking is enabled
- createInvoice in qbo-client.ts accepts optional classRef parameter
- CDC cron calls fetchAndCachePreferences once per org per cycle (with 23h cache check)
- QBO Health dashboard shows yellow warning banner when classTrackingEnabled is false
- Health API response includes classTrackingEnabled and locationTrackingEnabled fields
- Vendor CRUD routes exist (GET /api/vendors, POST /api/vendors, GET/PATCH/DELETE /api/vendors/[id])
- Vendor POST auto-links Materials with matching manufacturer name
- POST /api/invoices/[id]/credit endpoint exists and enqueues creditMemo:push
- sync-trigger route supports "vendors" and "employees" entity types
- All routes enforce auth via requireAuthSessionFirst and include orgId in all queries
- Build passes with zero TypeScript errors


**Add preferences fetch inside `pollOrgCdc()` function body** (or in the per-connection loop in the GET handler), ideally at the start of each org's processing:

```typescript
// Refresh QBO preferences (cached 23 hours)
const twentyThreeHoursAgo = new Date(Date.now() - 23 * 60 * 60 * 1000);
if (!connection.preferencesLastCheckedAt || connection.preferencesLastCheckedAt < twentyThreeHoursAgo) {
  try {
    await fetchAndCachePreferences(connection);
  } catch (prefError) {
    console.error(`[qbo-cdc] Failed to fetch preferences for org ${connection.orgId}:`, prefError);
    // Non-fatal — continue with CDC poll even if preferences fetch fails
  }
}
```

The preferences fetch is non-blocking — a failure does not stop the CDC poll. The 23-hour cache window means preferences are fetched roughly once per day even though the CDC cron runs every 4 hours.

- Fetch active QBO connection

- Return 200 `{ success: true, message: "Credit memo queued for sync to QuickBooks" }`

**2. Extend `src/app/api/integrations/qbo/sync-trigger/route.ts`:**

Add two new entity type cases to the POST handler's switch/if chain:

```typescript
case "vendors": {
  const vendors = await prisma.vendor.findMany({
    where: { orgId: auth.orgId, isActive: true, qboVendorId: null },
    select: { id: true },
  });
  for (const v of vendors) {
    await enqueue(auth.orgId, connection.id, "vendor", v.id, "push", 1);
  }
  return NextResponse.json({ queued: vendors.length, entityType: "vendors" });
}

case "employees": {
  const techs = await prisma.user.findMany({
    where: { orgId: auth.orgId, role: "TECH", qboEmployeeId: null },
    select: { id: true },
  });
  for (const t of techs) {
    await enqueue(auth.orgId, connection.id, "employee", t.id, "push", 1);
  }
  return NextResponse.json({ queued: techs.length, entityType: "employees" });
}
```
